Как устроено

Одно ядро, три тонких слоя

Логика, история и отрисовка написаны один раз в core.c. Слой под каждую ОС рисует только прямоугольники и текст и передаёт клики и клавиши в ядро.

        src/core.c  (718 строк)
  парсер · история · кнопки · отрисовка
        │            │            │
 plat_win32.c   plat_x11.c   plat_cocoa.m
 Win32 + GDI    Xlib         Cocoa
 206 строк      354 строки   154 строки

Где хранится история

  • Windows: %APPDATA%\MiniCalc\history.txt
  • Linux: ~/.local/share/minicalc/history.txt
  • macOS: ~/Library/Application Support/MiniCalc/history.txt

Почему C

Python, Electron, Java и .NET сами занимают десятки мегабайт и не влезают в 5 МБ. C с родным API даёт файлы 35–73 КБ и ни одной сторонней зависимости.

Что происходило, по порядку

  1. Окружение. Нашлись gcc, clang и libX11-dev. MinGW не было — поставил.
  2. Linux-слой, первый запуск в Xvfb. Окно работает, но кириллица не рисуется, RAM 5.9 МБ.
    5.9 МБ
  3. Оптимизация шрифтов. Xlib держал метрики на 65 536 символов, оставил только нужные. Если нет кириллических шрифтов, интерфейс сам переходит на английский.
    4.9 МБ
  4. Windows-слой. MinGW собрал .exe на 56 КБ, зависит только от системных DLL. В Wine 9.0 окно и кириллица в порядке.
    Wine ✓
  5. macOS-слой на Cocoa. Здесь собрать нельзя, поэтому собирает CI.
  6. 33 юнит-теста с AddressSanitizer и UBSan.
    33/33
  7. Убрал libm, вернул память шрифтов ОС. Linux: 2.6 МБ RSS, 1.0 МБ PSS.
    2.6 МБ
  8. Проверка мышью. 7 × 8 = 56, клик по истории, +1 = 113. История пережила перезапуск.
  9. CI, 4 прогона. Исправил по очереди: синтаксис YAML, триггер только на теги, mkdtemp на macOS и настоящий баг — на Mac история не сохранялась без родительской папки.
    macOS ✓Windows в CI ✗
  10. Zig 0.17.1. Скачал, сверил SHA256. zig cc с Linux собрал программы под macOS arm64 и x86_64, Linux glibc 2.28 и MiniCalc.exe (73 КБ). Остановился: вы прервали.
    кросс-сборка ✓build.zig

Рекомендации

По проекту, по порядку

  1. Внести фикс WM_DPICHANGED: CI станет зелёным, запустится замер RAM на Windows.
  2. Написать build.zig: одна команда zig build собирает все три ОС с любой машины.
  3. macOS-слой на C через Objective‑C runtime: Xcode и SDK станут не нужны.
  4. Linux: подгружать libX11 при запуске (dlopen). Тогда для сборки не нужны пакеты X11, а цель glibc 2.17–2.28 даст запуск на старых дистрибутивах.
  5. Проверить окно вживую на Windows и Mac.
  6. Подписать бинарники перед раздачей клиентам.

По моей работе

  • Проверять YAML и триггеры CI до пуша (actionlint).
  • Собирать Windows тем же компилятором, что в CI.
  • Давать короткий статус каждые 2–3 минуты.
  • Уточнять до старта: Zig как компилятор или как язык, как мерить 5 МБ на macOS.
  • Доводить один путь до зелёного CI, потом расширять.

Знать полезно: 5 МБ на macOS — физический предел Cocoa. Пустое окно AppKit уже занимает 10–20 МБ, а сам код калькулятора меньше 1 МБ.

Оркестрация и инструменты

Как реально работало

Всё вёл один агент последовательно: требования → архитектура → три слоя → тесты → CI → проверка Zig → отчёт. В фоне шли только установка пакетов и ожидание CI.

Десять субагентов для этого отчёта я не запускал. Вся информация уже была в этой сессии: агенты начали бы с нуля, перечитали бы то же самое и не уложились бы в 2–5 минут. Команда из 10 агентов имеет смысл для параллельной разработки (Windows, Linux, macOS и Zig одновременно). Её расклад есть в подробном отчёте.
