# CrowHub Studio — CLAUDE.md

## Миссия
CrowHub Studio — автономная веб-студия на автопилоте внутри холдинга. Владелец (Alex) в рутину не вмешивается.
Целевые метрики: 50 контактов/день, 5 сайтов/день, конверсия в оплату ≥10%.

## Структура
- Холдинг → CrowHub Studio (компания и бренд-зонтик) → продукты.
- FarmSite — продукт №1, подписка с пакетами и лимитами (см. `docs/product/plans.md`).
- Пайплайн: лид → исследование → сайт → правки → оплата → апсейл.
- Бренд-ассеты: GitHub FreeAiHub/farmsite-brand.

## Роли агентов (промпты в /agents)
1. Scout — ищет лиды: Telegram-группы Португалии, фриланс-биржи, Google Maps (нет сайта или он устарел).
2. Outreach — первый контакт в канале, где нашёлся лид. Тон человечный, деловой, без шаблонов.
3. Researcher — собирает данные о компании. Итог: brief.json.
4. Builder — генерирует сайт на 2–5 страниц из brief.json.
5. QA — проверяет сайт по чек-листу качества.
6. Closer — превью, правки, оплата, апсейл.
7. Video (HyperFrames) — промо-ролик сайта для превью и SMM (`/video`).

## Пайплайн и критерии приёмки
1. Лид → Google Sheets (лист Leads): имя, канал, контакт, источник.
2. Сборку начинаем только после явного «да» от лида. Заранее сайты не делаем.
3. Research → brief.json заполнен минимум на 80%.
4. Build → деплой на Cloudflare Pages, папка `clients/YYYY-MM-DD_client-name`.
5. QA → все пункты чек-листа пройдены.
6. Превью → ссылка, ролик и короткое человечное сообщение.
7. Правки → не больше 2 бесплатных раундов.
8. Оплата → клиент переносится в лист Clients.

## Бюджет и лимиты
- Сайт: ≤ $5 на токены и API, ≤ 2 часа от старта до превью.
- Стоимость и время каждого сайта пишем в Sheets (cost_usd, time_min).
- Превысили лимит → стоп и уведомление в Telegram-бот.

## Стандарты качества сайта
- Lighthouse: Performance ≥ 85, Accessibility ≥ 90, SEO ≥ 90. Сначала мобильная версия.
- Языки: PT по умолчанию, EN опционально. Тексты оригинальные.
- GDPR: cookie-баннер и политика конфиденциальности.
- Обязательно: WhatsApp-чат, футер «Made by CrowHub Studio», формы с копией на email Alex.

## Правила работы
- Отвечай Alex коротко, по-русски, по шагам.
- Сначала простое рабочее решение, потом усложняем.
- Перед удалением, тратами и сообщениями клиентам спрашивай подтверждение.
- Секреты храним только в `.env` (шаблон: `.env.example`), в git их не кладём.
- Каждый этап пишем в /logs.
