# CrowHub Studio — архитектура

## 1. Принцип
Широкий верх воронки, узкое производство. Много контактов → сайт только после явного «да».

```
 Scout ──► Qualifier ──► Outreach ──(«да»)──► Researcher ──► Builder ──► QA ──► Closer ──► Оплата ──► Апсейл
 200–300     score       100–300/день           brief.json     превью    Lighthouse  превью,    Stripe     хостинг,
 лидов/день  0–100       вопрос-согласие                                             2 правки   webhook    SEO, боты
   │           │            │  нет ответа → 1 follow-up → no_response
   │           │            │  отказ / «не пишите» → do_not_contact (навсегда)
   ▼           ▼            ▼                ▼             ▼          ▼         ▼          ▼
 ─────────────────────────── Google Sheets «CrowHub CRM» (единый источник правды) ───────────────────────────
                                              │
                         Telegram-бот: алерты Alex  ·  Голос Alex ↔ Claude: Tasks / Questions
```

## 2. Воронка и ожидаемые цифры (гипотеза, уточним на пилоте)
| Этап | В день | Конверсия |
|---|---|---|
| Найдено (Scout) | 200–300 | — |
| Квалифицировано | 100–150 | ~50% |
| Первое касание | 100 → 300 | — |
| Согласие «да» | 5–7 | ~5% |
| Собрано сайтов | 5–7 | 100% от «да» |
| Оплата | ~0,5–1 | ≥ 10% |

## 3. CRM — Google Sheets «CrowHub CRM»
| Вкладка | Назначение | Ключ |
|---|---|---|
| Dashboard | Воронка, деньги, открытые задачи (формулы) | — |
| Tasks | To-do проекта: этап, владелец, статус, критерий готовности, вопрос/ответ | `T-xxx` |
| Questions | Вопросы к Alex и решения | `Q-xxx` |
| Leads | Все лиды, статус воронки, доказательство согласия | `L-xxxxx` |
| Outreach | Журнал каждого сообщения (out/in), интент ответа | `M-xxxxxx` |
| Projects | Сайты: бриф → сборка → QA → превью → правки → оплата, cost/time | `P-xxxx` |
| Clients | Оплатившие, хостинг, MRR, апсейл | `C-xxxx` |
| Templates | Тексты сообщений; отправляем только `approved = yes` | `TPL-…` |
| Costs | Расход токенов/API по агентам и проектам | — |
| README | Описание вкладок и статусов | — |

### Статусы лида
`new → qualified → contacted → followup_1 → (replied) → consent_yes → converted`
Ветки выхода: `disqualified`, `consent_no`, `no_response`, `do_not_contact`.

### Статусы проекта
`research → build → qa → preview_sent → revision_1 → revision_2 → awaiting_payment → paid`
Ветки выхода: `lost`, `on_hold`.

### Правила записи
- Агент пишет в CRM после каждого шага (статус + время).
- `consent_yes` ставится только с `consent_proof` (цитата ответа или ссылка на сообщение).
- Строки не удаляем — меняем статус.

## 4. Управление голосом
Alex в голосовом режиме Claude (подключён Google Sheets):
| Alex говорит | Claude делает |
|---|---|
| «Что ждёт меня?» | Читает Tasks «Ждёт Alex» + Questions «Открыт» |
| «Ответ на Q-002: …» | Пишет ответ, статус «Отвечен», разблокирует задачу |
| «Отметь T-013 готово» | Статус «Готово», дата |
| «Добавь задачу: …» | Новая строка `T-xxx` |
| «Как воронка сегодня?» | Читает Dashboard |
| «Одобряю шаблон TPL-FC-PT» | `approved = yes` |

## 5. Компоненты и интеграции
| Компонент | Инструмент | Статус |
|---|---|---|
| CRM / to-do | Google Sheets | ✅ создано |
| Почта | Gmail (рабочий ящик, позже отдельный домен для рассылок) | подключено, нужен домен |
| Уведомления | Telegram-бот | ждёт токен |
| Хостинг превью | Vercel или Cloudflare Pages | Q-001 |
| Оплата | Stripe Payment Links + webhook | ждёт аккаунт |
| Расписание агентов | Запланированные задачи Claude | после пилота |

## 6. Безопасность
- Секреты только в `.env` (шаблон — `.env.example`), в git не попадают.
- Доступ к CRM — только аккаунт Alex и сервисные интеграции.
- Лимиты отправки на канал, чтобы не получить бан: email — прогрев с 20/день, Telegram/Instagram — до 20–30 новых диалогов/день с аккаунта.
